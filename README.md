# Pet shop sales ETL

Самостоятельная реализация лабораторной работы по ETL на Apache Spark. Pipeline читает десять CSV-файлов из `исходные данные`, сохраняет исходные строки и модель «звезда» в PostgreSQL, а затем рассчитывает шесть витрин и загружает их в ClickHouse.

Требования взяты из [описания лабораторной работы в L0ckR/BigDataSpark](https://github.com/L0ckR/BigDataSpark); реализация и структура этого проекта написаны отдельно.

## Запуск

Нужны Docker и Docker Compose. Из корня репозитория выполните:

```bash
docker compose up --build -d
docker compose logs -f spark
```

После строки `ETL_SUCCESS` Spark-контейнер завершится с кодом 0. Результат можно проверить в ClickHouse:

```bash
docker compose exec -T clickhouse clickhouse-client \
  --user lab --password lab --multiquery < sql/check_reports.sql
```

Для повторного запуска полного ETL:

```bash
docker compose run --rm spark
```

Перед загрузкой Spark очищает таблицы `raw` и `star`, а перед вставкой очищает витрины. Повторный запуск не накапливает копии строк. `docker compose down` останавливает сервисы и сохраняет данные в volumes; `docker compose down -v` удаляет также данные обеих баз.

## Компоненты

- `app/main.py` — чтение CSV, преобразования PySpark, загрузка по JDBC в PostgreSQL и отправка JSONEachRow в ClickHouse.
- `sql/postgres.sql` — схема для исходных данных и модели «звезда»; PostgreSQL выполняет его при первом старте пустого volume.
- `sql/clickhouse.sql` — DDL для шести витрин.
- `sql/check_reports.sql` — запросы для просмотра результатов.
- `docker-compose.yml` — PostgreSQL, ClickHouse и Spark job.

Порты на хосте: PostgreSQL `15432`, ClickHouse HTTP `18123`, ClickHouse native `19000`. Логин и пароль учебного стенда — `lab` / `lab`, база PostgreSQL — `bigdata`, база ClickHouse — `analytics`.

## Модель и расчёты

Каждая строка исходного CSV трактуется как одна продажа: в данных нет отдельного идентификатора заказа. Ключ продажи строится из имени файла и исходного `id`, потому что `id` начинается заново в каждом CSV. Ключи измерений рассчитываются как SHA-256 от полного набора нормализованных атрибутов, поэтому повторяющиеся числовые ID из разных файлов не сливают разные описания. Перед преобразованием Spark обрезает пробелы по краям текстовых полей, как SQL загрузка снежинки; пустые postal code и штат магазина становятся `NULL`, тогда как `raw` остается без изменений.

Витрины содержат ранги, чтобы топы можно было запросить через `ORDER BY ..._rank LIMIT N`. Категорийная и географическая выручка повторяется на каждой строке соответствующей группы. Для выручки используется исходное поле `sale_total_price`; средняя цена поставщика считается по наблюдениям `product_price`. Временная витрина включает месячные и годовые строки, а изменение сравнивается с предыдущим периодом того же типа.

В наборе рейтинг и счетчик отзывов записаны на каждой строке продажи и меняются между наблюдениями одного товара. Витрины показывают средний рейтинг и среднее наблюдаемое значение счетчика отзывов по паре «название + категория», считают проданные единицы и добавляют корреляцию рейтинга с объёмом продаж по этим агрегированным товарам. Это среднее по строкам источника, а не число уникальных отзывов.

Реализована обязательная загрузка в ClickHouse. Cassandra, Neo4j, MongoDB и Valkey в проект не включены: в задании они перечислены как дополнительные варианты.
